# 화면과 문서 표현 최종 점검

점검일: 2026-09-02

## 점검 범위

- 공개 제품 개발 사례 페이지와 검색·공유용 메타데이터
- 프로젝트 목록, 자산, 입찰, 배분안, 수거, 정산, 새 프로젝트 화면
- 대화상자, 오류와 빈 상태, 저장 결과 메시지, CSV 열 이름
- README와 제품, 분석, 설계, 인계, 품질 문서
- 가상 데이터 분석 보고서와 내장 데이터
- 제품 소개 화면 10장과 4분 제품 소개 영상

## 주요 용어 정리

| 이전 표현 | 최종 표현 | 정리 이유 |
| --- | --- | --- |
| 유휴 자산 | 처분해야 하는 사무 자산 | 사용자가 실제로 처리해야 하는 대상을 바로 설명 |
| 사무 자산 처분안 | 사무 자산을 어떻게 처분할지 | 첫 화면에서 추상 명사보다 사용자의 질문을 직접 제시 |
| 수요처 | 인수처 | 자산을 넘겨받는 대상이라는 뜻을 명확히 전달 |
| 현금 회수액, 매각 수익 | 매각 대금 | 입찰에서 받는 총액이라는 데이터의 의미에 맞춤 |
| 총 경제 효과 | 매각 대금과 비용 절감액 합계 | 계산식을 이름에 그대로 드러냄 |
| 자산군 | 자산 항목 | 화면에서 묶음보다 개별 항목을 다룬다는 점을 분명히 표현 |
| 매칭안 | 배분안 | 자산과 인수처의 배정 결과라는 의미를 구체적으로 표현 |
| 합성 시뮬레이션, 가상 데이터 검증 | 가상 데이터 분석, 가상 데이터로 판단 기준 점검 | 실제 고객 검증으로 오해하지 않도록 분석 목적을 명시 |
| 대표 시나리오 | 예시 결과 | 설명용 샘플이라는 한계를 자연스럽게 전달 |
| 가격 수용도 | 실제 지불 의향 | 다음 파일럿에서 확인할 행동을 구체적으로 표현 |

## 시각 비교

`before`에는 수정 전 화면, `after`에는 같은 1440×1024 화면의 최종 결과가 있습니다. `compare`는 두 화면을 왼쪽과 오른쪽에 나란히 배치한 검수 자료입니다.

- 공개 제품 개발 사례: `compare/01-landing.png`
- 프로젝트 목록: `compare/02-projects.png`
- 배분안: `compare/03-matching.png`
- 입찰: `compare/04-bids.png`
- 자산: `compare/05-assets.png`
- 수거: `compare/06-pickups.png`
- 정산: `compare/07-settlements.png`
- 새 프로젝트: `compare/08-new-project.png`
- 가상 데이터 분석 보고서: `compare/09-report.png`

문구 길이가 바뀐 뒤에도 제목, 핵심 지표, 표 열, 버튼, 원형 아이콘이 잘리거나 어긋나지 않았습니다. 수정 전 화면은 변경 근거를 보존하기 위해 그대로 두었으며, 현재 서비스와 문서에서는 이전 표현을 사용하지 않습니다.

## 문서 플러그인 개선

문서 표현 검토 플러그인에 다음 검사를 추가했습니다.

- 독자용 용어를 바꾸기 전에 원래 뜻, 쉬운 표현, 기술 문서에서 유지할 표현을 표로 정리
- 사용자가 지적한 단어뿐 아니라 같은 모호함을 가진 유사 표현, 제목, 메타데이터, 대체 텍스트, 생성 산출물까지 검색
- 익숙한 단어로 바꿨더라도 데이터의 회계적·제품적 의미가 정확한지 다시 확인
- 일괄 수정 뒤 조사 오류, 중복 명사, 단위 변경과 남은 유사 표현을 검사
- `유휴 자산`, `매각 수익`, `가상 데이터 검증`, `대표 시나리오`, `가격 수용도` 같은 표현을 독자용 문구에서 검토 대상으로 표시

## 판정

현재 사용자 화면, 문서, 보고서, 스크린샷과 영상에서 이번에 정한 이전 표현과 조사 오류는 발견되지 않았습니다. 브라우저 비교에서도 문구 변경으로 생긴 잘림, 겹침 또는 정렬 문제는 없습니다.
