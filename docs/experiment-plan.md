# 신규 사업 실험 계획

> 현재 상태: 제품 MVP를 만들고 가상 데이터로 판단 기준까지 점검했지만, 실제 고객 파일럿과 매출은 아직 검증하지 않았습니다.

## 문제 정의

오피스 이전과 폐점 때 자산 담당자는 중고 매입업체, 폐기업체, 기부처, 임직원 판매를 따로 조율합니다. 높은 판매가만 선택하면 수거가 분산되고, 일정을 우선하면 재사용 가능한 자산까지 폐기될 수 있습니다. 판단 근거가 여러 문서에 흩어져 승인도 늦어집니다.

## 초기 고객

- 50개 이상의 사무 자산을 한 번에 처분하는 100인 이상 기업
- 오피스 이전, 통폐합, 리뉴얼을 3개월 안에 앞둔 총무 또는 자산 담당자
- 매각 대금뿐 아니라 폐기 비용, 환경 지표와 철수 일정을 함께 책임지는 팀

## 가장 위험한 가설

1. 담당자는 개별 최고가보다 매각 대금과 폐기비, 운반비 절감액을 합한 금액을 더 중요한 승인 근거로 사용한다.
2. 재사용률과 수거 횟수를 함께 제시하면 경영진 승인 시간이 줄어든다.
3. 사업자 확인을 마친 인수처 네트워크에 중개 수수료 또는 성공 수수료를 지불할 의사가 있다.
4. 입찰을 여러 인수처로 나눠도 수거가 세 번 이하면 운영 부담을 수용한다.

## MVP에서 측정할 퍼널

| 단계 | 이벤트 | 성공 기준 |
| --- | --- | --- |
| 배분안 노출 | `dashboard_viewed` | 파일럿 담당자 10명 이상 |
| 인수처 확인 자료 검토 | `bids_opened` | 노출 대비 60% 이상 |
| 조건 탐색 | `recalculation_opened` | 노출 대비 30% 이상 |
| 배분안 확정 화면 진입 | `confirmation_opened` | 노출 대비 20% 이상 |
| 실제 파일럿 | 운영 인터뷰 | 기업 5곳 중 3곳 이상 |

보조 지표는 첫 화면에서 배분안 확정 화면 진입까지 걸린 시간, 재계산 횟수, 기준 미충족 비율, 수거 회차 변경 횟수입니다.

`dashboard_viewed`와 `bids_opened`는 각 페이지 진입을 뜻합니다. 클릭과 페이지 노출을 같은 이름으로 중복 기록하지 않습니다. 파일럿 분석에서는 사용자, 프로젝트, 이벤트 이름을 기준으로 최초 발생 시각을 사용해 퍼널을 계산합니다. 동일 사용자가 새 세션에서 다시 검토한 행동은 재방문 지표로 별도 집계합니다.

```sql
SELECT
  project_id,
  user_id,
  min(CASE WHEN name = 'dashboard_viewed' THEN occurred_at END) AS dashboard_at,
  min(CASE WHEN name = 'bids_opened' THEN occurred_at END) AS bids_at,
  min(CASE WHEN name = 'recalculation_opened' THEN occurred_at END) AS recalculation_at,
  min(CASE WHEN name = 'confirmation_opened' THEN occurred_at END) AS confirmation_at
FROM analytics_events
GROUP BY project_id, user_id;
```

## 수익 가설

- 매각 금액의 8% 성공 수수료
- 비용 절감액의 10% 성과 수수료
- 대기업용 검수, 운송, ESG 증빙을 포함한 프로젝트 이용료

첫 파일럿은 과금 방식을 확정하기보다 지불 의사와 승인자의 판단 기준을 확인하는 데 집중합니다.

## 4주 검증 계획

### 1주차

실제 이전 또는 폐점을 앞둔 담당자 10명을 인터뷰하고 최근 처분 자료를 수집합니다. 승인 기준과 현재 소요 시간을 확인합니다.

### 2주차

같은 자산 묶음에 대한 인수처 입찰을 수작업으로 확보합니다. 제품에는 검증을 마친 입찰만 넣어 배분안 검토 과정을 확인합니다.

### 3주차

기업 5곳에 MVP를 제공하고 화면 공유 없이 직접 사용하게 합니다. 행동 이벤트, 질문, 재계산 조건을 기록합니다.

### 4주차

최소 2개 프로젝트에서 실제 수거 의향서 또는 유료 파일럿 합의를 확보합니다.

## 투자 판단

| 결과 | 판단 |
| --- | --- |
| 유료 파일럿 참여 기업 2곳 이상, 배분안 확정 화면 진입률 20% 이상 | 전담 개발 인력 투입 |
| 사용성 지표는 충족하지만 지불 의사 부족 | 가격과 구매자 재검증 후 2주 반복 |
| 인수처 확인 자료 검토율 40% 미만 | 문제와 정보 구조 재정의 |
| 고객이 개별 최고가만 선택 | 통합 매칭 가설 중단 |

운영 전환을 판단할 때는 거래 실패율, 수거 지연, 개인정보 사고와 사업자 확인을 마치지 않은 인수처의 비율을 중단 기준에 반드시 포함합니다.

### 실제 파일럿 전 규칙 점검

같은 결과를 재현할 수 있는 가상 데이터로 위 판단 기준의 민감도를 점검했습니다. 모든 기준을 동시에 충족할 추정 확률은 18.8%, 확정 화면 진입 기준과 유료 파일럿 기준을 함께 충족할 추정 확률은 30.9%였습니다. 소규모 실제 파일럿은 진행하되 전담 개발 인력 투입은 보류합니다.

이 수치는 실제 고객 조사나 운영 기록이 아닙니다. [가상 데이터 분석 보고서](./validation-simulation.md)와 [데이터 품질 판정](./validation-data-quality.md)에 분석 방법, 재현 방법과 표현할 수 없는 내용을 기록했습니다.

## 의도적으로 생략한 범위

- 공개 인수처 가입과 실명 인증 자동화
- 결제사 연동과 실제 에스크로
- 운송사 배차 최적화
- 대용량 엑셀 자동 가져오기와 원본 파일 보존
- LLM 문서 추출과 제안서 자동 생성

파일럿에서 사용자의 배분안 확정 의향을 확인한 뒤 필요한 기능부터 추가합니다.
