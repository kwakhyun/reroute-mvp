# 변경 이력과 검증 범위

## 2026-10-22 전체 검토 후 수정

- 공개 홈을 요청 시 렌더링해 요청별 CSP nonce가 React 스크립트에 적용되도록 했습니다. 브라우저 테스트는 nonce와 데모 버튼의 진행 상태를 함께 확인합니다.
- 재사용률의 표시용 반올림과 기준 판정을 분리했습니다. 실제 수량으로 판단하며 소수 기준의 부동소수점 오차도 처리합니다. 이전 버전에서 기준 통과로 저장된 초안도 확정 시 다시 검사하고 화면에 같은 판정을 표시합니다.
- 프로젝트 생성 중 CSV 오류가 발생해도 입력값과 선택 파일을 보존합니다. 생성과 재계산 화면 모두 정수 단위의 최소 매각 금액을 받습니다.
- 재계산 저장 직후 화면을 갱신합니다. 완료 버튼, 닫기 버튼과 Escape가 같은 종료 처리를 사용하며 요청 중에는 창을 닫지 않습니다. 첫 배분안을 만들 때도 완료 창의 상태를 유지합니다.
- DB 관리 명령과 standalone 시작 명령이 Next.js의 환경 파일 우선순위를 따르도록 했습니다. 셸 환경 변수는 파일보다 우선합니다.
- DB 초기화는 정규화한 경로의 `data` 경계, 심볼릭 링크, 인코딩된 경로를 검사합니다. 검증한 경로를 마이그레이션과 시드에도 전달합니다.

실행 결과와 검증 환경은 [검증 보고서](../verification-report.md)에 기록합니다. 이전 시점의 테스트 수와 측정값은 아래에 그대로 남깁니다.

## 기능과 화면의 변화

- CSV 교체 전에 기존/새 입찰 수, 삭제될 초안과 계산 가능 여부를 확인하는 미리보기를 추가했습니다. 기존 제품 소개 영상에는 이 단계가 없습니다.
- 숫자 공란과 같은 확인 자료의 상충하는 내용을 거절합니다. 미리보기의 파일, 사용자, 프로젝트 버전과 만료 시각도 교체 시점에 재검증합니다.
- 중간 화면 폭에서는 배분 표를 세로로 배치하고, 실제로 넘치는 표에만 스크롤 안내를 제공합니다. 입찰 목록은 페이지당 50건을 조회합니다. 기존 화면 캡처는 촬영 당시의 배치입니다.
- 조회와 변경 서비스의 책임을 분리하고, 기능별 CSS Modules를 적용했습니다. 이번 개선에서 DB 스키마와 의존성은 변경하지 않았습니다.
- 인수처와 입찰은 50행씩 같은 트랜잭션에 저장합니다. 매칭 계산은 반복되는 날짜 변환과 합계 연산을 줄였으며 10만 조합과 1.5초 제한은 유지했습니다.

## 2026-09-05 UI 리뉴얼

홈부터 정산까지 노란색 강조, 흰색 카드, 회색 작업 배경과 굵은 산세리프 제목으로 통일했습니다. 홈의 서비스 소개 카드, 프로젝트 현황 요약과 작업 공간 헤더를 추가하고 로그인 입력창의 공통 스타일 적용을 보완했습니다. 색상과 배치 규칙은 [디자인 시스템](./design-system.md)에 기록했습니다.

현재 제품 미리보기는 `public/product`에 보관합니다. 기존 `public/portfolio/walkthrough-frames`, 시연 영상과 이전 QA 캡처는 촬영 당시의 화면이며 소급해 교체하지 않습니다. 이 UI 리뉴얼은 계산 규칙, 권한, 확정 절차, DB 스키마와 아래 샘플 수치를 변경하지 않습니다.

## 동시성 검증의 경계

개선 전 경쟁 테스트는 실제 DB에서 CAS와 트랜잭션을 확인했지만, 서비스의 SQL 흐름을 테스트 안에 별도로 구현했습니다. 실제 서비스와 브라우저 사이의 모든 경계 조건까지 검증한 것은 아닙니다. [당시 테스트 소스](https://github.com/kwakhyun/reroute-mvp/blob/bb506103ba28148ea6fe3aad7baea357c4f1ffd7/src/server/db/concurrency.test.ts)에서 이 범위를 확인할 수 있습니다.

후속 검토에서는 확인창을 연 뒤 다른 사용자가 재계산하면 검토하지 않은 최신 배분안을 확정할 수 있는 경로를 발견했습니다. 현재는 사용자가 검토한 배분안 ID와 프로젝트 버전을 서버에서 다시 검사합니다. 실제 서비스 호출로 테스트를 바꾸고, 읽기와 트랜잭션 사이의 재계산, 동일 요청 재시도, 로컬 파일 DB 경쟁과 실패 후 복구를 검증했습니다. 이 수정과 테스트 확대를 이전 버전의 검증 결과에 소급하지 않습니다.

## 유지한 제품 범위와 수치

- 업무 흐름: 자산과 입찰 가져오기 → 계산 → 검토 및 확정 → 수거 → 외부 결제사 상태 확인
- 샘플: 자산 214개, 입찰 11건, 매각 대금 1,840만 원, 비용 절감액 300만 원, 합계 2,140만 원, 재사용률 86.9%
- 기술 구성: Next.js 16, React 19, TypeScript, Drizzle, libSQL/Turso, 관계형 테이블 16개
- 가상 분석: 사용자 10명, 기업 5곳, 50,000회 반복, 난수 초기값 20260901, 추정 확률 18.8%와 30.9%, 참여 의향 1/5
- 후속 개발 검토 기준: 기업 2곳 이상 유료 파일럿 참여 의향과 확정 화면 진입률 20% 이상

가상 분석은 실제 고객 성과가 아니며, 실제 결제, 운송 연동, SSO/MFA와 비동기 대용량 처리는 운영 전 보완 과제로 유지합니다. 로컬 계산 최적화와 5,000행 저장 테스트가 운영 부하 검증을 대신하지 않습니다.

공유 데모에는 다른 방문자의 수정 상태가 남을 수 있습니다. 로그인 화면에서 초기 상태를 복원하면 샘플을 다시 확인할 수 있습니다. 실행 조건과 한계는 [검증 보고서](../verification-report.md), 최적화 측정 조건은 [성능 문서](./performance.md)에 기록했습니다.
