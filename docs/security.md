# 보안과 운영 체크리스트

## 현재 구현된 경계

- HttpOnly, SameSite 쿠키와 운영 환경의 Secure 속성
- DB에는 세션 원문 대신 HMAC 해시 저장
- scrypt 비밀번호 해시와 타이밍 안전 비교
- 비밀번호 검증 전에 원자적으로 예약하는 로그인 시도 제한과 식별자 해시
- 조직 멤버십과 프로젝트 범위를 포함한 서버 측 역할 검사
- Zod 입력 검증
- 트랜잭션, 상태 조건 갱신, 요청 중복 방지
- 감사 로그와 최소화된 IP 해시
- CSV 수식 주입 방어
- 자산과 입찰 CSV의 크기, 행 수, 열, 값 검증, 수식 주입 방어
- 5MB 파일 상한과 multipart 여유를 반영한 6MB Server Action 및 Proxy 요청 제한
- 실제로 제공되는 네 개의 내장 이미지 경로만 허용하는 자산 이미지 카탈로그
- 파트너 검증 참조값, 검증자, 검증 시각, 만료일 저장과 재계산·확정 시점의 만료 입찰 차단
- 가져온 파트너 식별자를 프로젝트 범위로 파생해 다른 프로젝트의 검증 근거 덮어쓰기 차단
- 요청별 nonce와 `strict-dynamic`을 사용한 운영 CSP, 클릭재킹 방어, MIME 스니핑 방어, 권한 정책
- Vercel 또는 `TRUST_PROXY_HEADERS=true`인 알려진 프록시에서만 전달 IP 헤더 신뢰
- DB 트리거로 교차 프로젝트 입찰과 불일치 배정 차단
- API와 사용자 데이터 응답의 `private, no-store`
- 운영 DB 설정 누락 시 시작 차단, 파일 DB 사용 시 명시적 허용과 영속 볼륨 요구
- 상태 확인에서 마이그레이션 수, 핵심 테이블, 무결성 트리거 검사

## 배포 전 필수 항목

1. 32자 이상의 무작위 `SESSION_PEPPER`를 비밀 저장소에서 주입합니다.
2. `DEMO_MODE=false`를 정책으로 강제합니다.
3. HTTPS만 허용하고 HSTS가 프록시에서 유지되는지 확인합니다.
4. 원격 DB 토큰을 읽기와 쓰기 용도로 분리합니다.
5. DB 백업, 복구 훈련, 마이그레이션 롤백 절차를 준비합니다.
6. 오류 추적 서비스에는 쿠키, 이메일, 원본 IP를 전송하지 않습니다.
7. 세션 만료 데이터와 로그인 시도 데이터에 보존 기간을 적용합니다.
8. 실제 결제와 에스크로는 인가된 결제사를 통해 구현합니다.
9. `LOG_DRAIN_URL`을 운영 로그 수집기에 연결하고 오류율과 상태 확인 경보를 활성화합니다.
10. 자체 호스팅 프록시가 전달 헤더를 덮어쓰는 구성이 확인된 경우에만 `TRUST_PROXY_HEADERS=true`를 설정합니다.

## 다음 보안 단계

- OIDC SSO와 다중 인증
- 세션 회전과 전체 세션 폐기
- CSRF와 Origin 정책에 대한 프록시 통합 테스트
- 감사 로그 변경 방지 저장소
- 파트너 서류 업로드 시 악성 파일 검사
- 멤버십 초대, 해지, 역할 변경에 대한 이중 승인과 감사 정책
- 의존성 자동 업데이트와 정적 분석. 스키마 생성기는 고정 버전 일회성 실행으로 격리합니다.

현재 MVP는 샘플 데이터만 사용합니다. 실명, 계좌, 실제 거래 서류를 저장하도록 범위를 넓히기 전에 개인정보 처리 영향과 보존 정책을 별도로 검토해야 합니다.
