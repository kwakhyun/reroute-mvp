# 제품 판단 기록

> 이 문서는 기업 미팅 회의록이 아닙니다. 실험 계획, 코드, 테스트와 QA 산출물에서 확인할 수 있는 프로젝트 판단을 요약한 로그입니다.

## 매각 대금과 비용 절감액 합계를 핵심 승인 지표로 선택

- 문제: 개별 매각가만으로는 폐기비와 운반비, 재사용 성과와 수거 제약을 함께 판단할 수 없습니다.
- 판단: 매각 대금과 폐기비 및 운반비 절감액을 더한 금액을 화면에서 가장 먼저 보여 줍니다.
- 확인 방법: 매칭 정책과 핵심 지표 화면, 실험 계획의 퍼널로 확인합니다.

## 추천 엔진을 결정론적으로 제한

- 문제: 가설 검증 단계에서 설명하기 어려운 추천은 결정권자의 신뢰를 낮출 수 있습니다.
- 판단: 작은 입찰 조합을 상한이 있는 완전 탐색으로 계산하고, 같은 입력에는 항상 같은 결과를 반환합니다.
- 교체 시점: 입찰 후보와 조건의 수가 상한을 넘으면 비동기 최적화 서비스로 분리합니다.

## 버전 충돌과 중복 요청을 MVP 단계부터 방지

- 문제: 재계산과 확정이 겹치면 확정된 수거 일정에 서로 다른 데이터가 반영될 수 있습니다.
- 판단: 프로젝트 버전 비교 갱신, 트랜잭션과 중복 요청 방지 키를 적용했습니다.
- 확인 방법: 실제 SQLite 경쟁 테스트에서 하나의 최종 상태만 반영되는지 확인했습니다.

## 실제 결제와 운송 최적화를 생략

- 문제: 외부 연동은 사용자가 배분안을 실제로 확정할지 확인하는 데 필요하지 않고 구현 비용도 큽니다.
- 판단: 수거는 진행 상태만 기록하고, 정산은 외부 결제사에서 확인한 상태만 제공합니다.
- 한계: 자금 이체나 차량 배차 최적화는 수행하지 않습니다.

## 가상 데이터 분석 후 전담 개발 인력 투입을 보류

- 근거: 기준 시나리오에서 모든 기준을 동시에 충족할 추정 확률은 18.8%, 개발 인력 투입 기준을 충족할 추정 확률은 30.9%였습니다. 예시 결과에서는 기업 5곳 중 1곳이 유료 파일럿에 참여했습니다.
- 판단: 실제 기업 5곳을 대상으로 소규모 파일럿을 진행하되, 전담 개발 인력 투입은 보류합니다.
- 다시 판단할 조건: 실제 파일럿에서 유료 참여 기업 2곳과 배분안 확정 화면 진입률 20%를 함께 충족해야 합니다.
- 주의: 위 수치는 실제 고객 검증 결과가 아닙니다.
