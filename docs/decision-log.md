# 제품 판단 기록

> 이 문서는 기업 미팅 회의록이 아닙니다. 실험 계획, 코드, 테스트와 QA 산출물에서 확인할 수 있는 제품 결정을 정리한 문서입니다.

## 매각 대금과 비용 절감액 합계를 핵심 승인 지표로 선택

- 문제: 개별 매각가만으로는 폐기비와 운반비, 재사용 성과와 수거 제약을 함께 판단할 수 없습니다.
- 판단: 매각 대금에 폐기비와 운반비 절감액을 더한 금액을 화면에서 가장 먼저 보여 줍니다.
- 확인 방법: 매칭 정책과 핵심 지표 화면, 실험 계획의 퍼널로 확인합니다.

## 배분 계산을 결정론적으로 제한

- 문제: 같은 입력에서 결과가 달라지거나 계산 근거를 설명하기 어려우면 승인 자료로 쓰기 어렵습니다.
- 판단: 작은 입찰 조합을 상한이 있는 완전 탐색으로 계산하고, 같은 입력에는 항상 같은 결과를 반환합니다.
- 교체 시점: 입찰 후보와 조건의 수가 상한을 넘으면 비동기 최적화 서비스로 분리합니다.

## 버전 충돌과 중복 요청을 MVP 단계부터 방지

- 문제: 재계산과 확정이 겹치면 확정된 수거 일정에 서로 다른 데이터가 반영될 수 있습니다.
- 판단: 프로젝트 버전 비교 갱신, 트랜잭션과 중복 요청 방지 키를 적용했습니다.
- 확인 방법: 실제 SQLite 경쟁 테스트에서 하나의 최종 상태만 반영되는지 확인했습니다.

## 실제 결제와 운송 최적화를 생략

- 문제: 외부 연동은 사용자가 배분안을 실제로 확정할지 확인하는 데 필요하지 않고 구현 비용도 큽니다.
- 판단: 수거는 진행 상태만 기록하고, 정산은 외부 결제사에서 확인한 상태만 제공합니다.
- 한계: 자금 이체나 차량 배차 최적화는 수행하지 않습니다.

## 가상 데이터로 후속 개발 검토 기준을 점검

- 근거: 기준 시나리오에서 모든 기준을 동시에 충족할 추정 확률은 18.8%, 후속 개발 검토 기준을 충족할 추정 확률은 30.9%였습니다. 예시 결과에서는 가상 기업 5곳 중 1곳에 유료 파일럿 참여 의향이 있다고 가정했습니다.
- 판단: 시뮬레이션만으로 후속 개발 여부를 결정할 수 없습니다. 실제 사업 환경에서는 사업팀이 기업 5곳 이내를 대상으로 고객의 지불 의사와 계약 주체를 우선 확인하는 검증안을 설계했습니다.
- 다시 판단할 조건: 사업팀이 실제 고객을 검증할 때 기업 2곳 이상에서 유료 파일럿 참여 의향을 확인하고, 테스트 사용자 중 20% 이상이 배분안 확정 화면에 도달해야 합니다.
- 주의: 위 수치는 실제 고객 검증 결과가 아닙니다.
- 실행 범위: 개인 프로젝트에서는 참여 기업을 모집하거나 영업하지 않았고, 계약도 체결하지 않았습니다.
