# 제품 의사결정 로그

> 이 문서는 기업 미팅 회의록이 아닙니다. 실험 계획, 코드, 테스트와 QA 산출물에서 확인할 수 있는 프로젝트 판단을 요약한 로그입니다.

## 통합 회수 가치를 핵심 승인 근거로 선택

- 문제: 개별 매각가는 폐기비, 재사용, 수거 제약을 반영하지 못함
- 판단: 현금 회수액과 비용 절감액을 합한 순경제효과를 첫 번째 지표로 사용
- 확인 방법: 매칭 엔진 정책과 KPI 화면, 실험 계획의 퍼널

## 추천 엔진을 결정론적으로 제한

- 문제: 가설 검증 단계에서 설명할 수 없는 추천은 승인 신뢰를 낮출 수 있음
- 판단: 작은 입찰 조합을 상한이 있는 완전 탐색으로 계산하고 동일 입력에 항상 동일한 결과를 반환
- 교체 시점: 입찰 후보와 제약 수가 상한을 넘으면 비동기 최적화 서비스로 분리

## 버전 충돌과 중복 요청을 MVP에서부터 방지

- 문제: 재계산과 확정이 겹치면 운영 인계 데이터가 어긋날 수 있음
- 판단: 프로젝트 버전 CAS, 트랜잭션, 요청 멱등성 키를 적용
- 확인 방법: 실제 SQLite 경쟁 테스트에서 하나의 마지막 상태만 커밋되는지 확인

## 실제 결제와 운송 최적화를 생략

- 문제: 외부 연동은 매칭안 확정 의도라는 최우선 가설에 답하지 않고 구현 시간이 큼
- 판단: 수거는 상태 전이, 정산은 외부 확인 상태만 제공
- 한계: 자금 이동이나 배차 최적화를 수행하지 않음

## 합성 검증 후 전담 투자를 보류

- 근거: 기준 시나리오에서 모든 기준 동시 충족 추정 확률 18.8%, 투자 규칙 충족 30.9%, 대표 합성 코호트의 유료 파일럿 1/5개사
- 판단: 실제 5개사 제한 파일럿을 진행하되 전담 개발 투자는 보류
- 재판단 조건: 유료 파일럿 2개사와 확정 의도율 20%를 실측으로 함께 충족
- 주의: 이 수치는 실제 고객 검증 결과가 아님
