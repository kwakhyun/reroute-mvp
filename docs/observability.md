# 모니터링과 경보 기준

서버 로그는 한 줄짜리 JSON으로 표준 출력에 남깁니다. `LOG_DRAIN_URL`이 설정되어 있으면 같은 이벤트를 HTTPS 로그 수집기로 전송하고, 인증이 필요한 경우 `LOG_DRAIN_TOKEN`을 비밀 변수로 주입합니다. URL 쿼리, 쿠키, 요청 본문과 세션 토큰은 기록하지 않습니다.

Next.js 렌더링과 서버 액션 오류는 `next_request_failed`로 수집합니다. API 라우트는 공통 요청 래퍼를 사용해 성공과 실패를 모두 `http_request_completed`로 기록합니다. 이를 바탕으로 상태 코드별 요청 수와 지연 시간을 집계할 수 있습니다.

처리되지 않은 API 예외는 요청 ID, 경로와 오류 종류를 포함한 `http_request_failed`로 먼저 기록합니다. 응답의 `X-Request-Id`로 해당 로그를 찾을 수 있습니다.

`/api/health`는 DB 연결 상태와 함께 적용된 마이그레이션 수, 핵심 테이블 다섯 개, 프로젝트 무결성 트리거 네 개를 확인합니다. 모든 조건을 충족하면 `ready`를 반환하고, 하나라도 충족하지 못하면 503과 `not_ready`를 반환합니다.

## 권장 SLO와 경보

- 가용성: 30일 기준 `/api/health` 성공률 99.9% 이상
- API 서버 오류율: 5분 동안 `http_request_completed` 전체 건수 대비 5xx가 1%를 초과하면 경고, 5%를 초과하면 긴급
- 상태 확인 지연: 5분 동안 p95 500ms 초과 시 경고
- 로그 전송 실패: `log_drain_delivery_failed`가 10분 동안 3회 이상이면 수집기 연결과 토큰 확인
- 매칭 계산 용량 초과: 동일 프로젝트에서 10분 동안 3회 이상이면 후보 축소 또는 비동기 작업 큐 전환

긴급 경보가 발생하면 최근 배포와 마이그레이션을 먼저 확인합니다. 이어서 `/api/health` 응답, 데이터베이스 접속 상태, 오류 이벤트의 `routePath`와 `requestId` 순서로 원인을 좁힙니다.

복구 후에는 감사 로그와 실제 데이터 변경 내역을 대조합니다. 전체 페이지 요청 수와 분산 추적 데이터는 배포 플랫폼의 Web Analytics 또는 OpenTelemetry를 연결해 보완합니다.
