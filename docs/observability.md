# 운영 관측과 경보 기준

서버 로그는 한 줄 JSON으로 표준 출력에 남고 `LOG_DRAIN_URL`이 있으면 같은 이벤트를 HTTPS 로그 수집기로 전송합니다. 인증이 필요한 수집기는 `LOG_DRAIN_TOKEN`을 비밀 변수로 주입합니다. URL 쿼리, 쿠키, 요청 본문, 세션 토큰은 기록하지 않습니다.

Next.js 렌더링과 서버 액션 오류는 `next_request_failed`로 수집합니다. API 라우트는 공통 요청 래퍼를 사용해 성공과 실패를 모두 `http_request_completed`로 기록하므로 상태 코드별 요청 수와 지연 시간의 분모를 계산할 수 있습니다. 처리되지 않은 API 예외는 요청 ID, 경로, 오류 종류와 함께 `http_request_failed`로 먼저 기록하고, 응답의 `X-Request-Id`로 로그와 연결합니다. URL 쿼리와 본문은 기록하지 않습니다.

`/api/health`는 단순 연결 여부가 아니라 적용된 마이그레이션 수, 핵심 테이블 다섯 개, 프로젝트 무결성 트리거 네 개를 확인합니다. 조건을 충족하면 `ready`, 그렇지 않으면 503과 `not_ready`를 반환합니다.

## 권장 SLO와 경보

- 가용성: 30일 기준 `/api/health` 성공률 99.9% 이상
- API 서버 오류율: 5분 동안 `http_request_completed` 전체 건수 대비 5xx가 1%를 초과하면 경고, 5%를 초과하면 긴급
- 상태 확인 지연: 5분 동안 p95 500ms 초과 시 경고
- 로그 드레인 실패: `log_drain_delivery_failed`가 10분 동안 3회 이상이면 연결과 토큰 확인
- 매칭 계산 용량 초과: 동일 프로젝트에서 10분 동안 3회 이상이면 후보 축소 또는 비동기 작업 큐 전환

긴급 경보 발생 시 최근 배포와 마이그레이션을 확인하고 `/api/health`, 데이터베이스 연결, 오류 이벤트의 `routePath`와 `requestId` 순서로 범위를 좁힙니다. 복구 후 감사 로그와 실제 데이터 변경 여부를 대조합니다. 페이지 요청의 전체 분모와 분산 추적은 배포 플랫폼의 Web Analytics 또는 OpenTelemetry를 연결해 보완합니다.
