# 개발팀 인계 문서

## 검증 대상

한 화면에서 자산 목록, 입찰 근거, 순경제효과, 재사용률과 수거 조건을 검토하고 확정하는 과정이 실제 승인 시간을 줄이는지 확인합니다.

## 재사용 가능한 산출물

- Drizzle 스키마, 순차 마이그레이션, 기존 데이터 보존 회귀 테스트
- 결정론적 매칭 엔진과 단위 테스트
- 인증, 조직 멤버십, 프로젝트 역할, 세션 경계
- 요약, 감사 로그, CSV API 계약
- 프로젝트 버전 CAS를 사용하는 재계산과 확정 트랜잭션, 실제 DB 경쟁 테스트
- 레코드 수정 시각을 비교하는 수거와 정산 CAS, 상태별 운영 필수값 검증
- 사용자 행동 이벤트 정의
- 고정 시드 합성 검증 생성기, 실행 노트북, 원본 CSV/JSON, 단일 HTML 보고서
- 성공 기준과 중단 조건, 투자 보류 근거를 연결한 제품 의사결정 로그
- 반응형 화면과 디자인 토큰
- 자산 CSV와 검증 근거가 포함된 입찰 CSV 가져오기, 수거 상태 변경, 외부 정산 확인 상태
- CI와 컨테이너 빌드

## 확정된 도메인 결정

- 금액은 만 원 단위 정수로 저장합니다.
- 추천안은 전체 자산 수량을 정확히 배정해야 합니다.
- 각 자산군은 검증을 마친 수요처의 입찰 하나에 전체 수량을 배정해야 합니다.
- 확정 전 초안은 다시 계산할 수 있고 확정 후에는 잠깁니다.
- 현금 회수액과 비용 절감액의 합을 순경제효과로 정의합니다.
- 같은 날짜의 수거는 한 회차로 계산합니다.
- 확정은 반드시 감사 로그를 남깁니다.
- 외부 정산 확인은 자금을 이체하지 않으며 결제사 확인 번호만 기록합니다.
- 프로젝트의 유효 현금 회수 하한은 프로젝트 설정액과 자산별 회수 기준액 합계 중 큰 값입니다.
- 모든 입찰에는 검증 담당자, 확인 시각과 확인 근거가 있어야 합니다. 검증이 만료된 입찰은 매칭 후보에서 제외합니다.

## 한계와 교체 지점

| 현재 MVP | 운영 전환 시 |
| --- | --- |
| 조직 멤버십을 바탕으로 한 프로젝트 격리 | SSO 그룹 동기화와 멤버십 생성, 변경, 해지 절차 |
| 상한이 있는 작은 조합 탐색 | 큐 기반 비동기 제약 최적화 서비스 |
| 데모 계정 | OIDC SSO, MFA, 사용자 수명주기 |
| 외부 정산 상태 수동 확인 | 결제사 계약, 서명된 웹훅, 이중부기 원장 |
| 자산 CSV와 검증을 마친 입찰 데이터 | 대용량 엑셀 가져오기, 검증 대기열, 원본 보존 |
| 단일 앱 트랜잭션 | 아웃박스와 이벤트를 이용한 수거 운영 전달 |
| 고정 시드 합성 검증 | 실제 파일럿 이벤트, 인터뷰 원문, 계약과 지불 증빙 |

## 현재 의사결정 상태

- 실제 고객 검증 전 단계이며 합성 데이터는 수요 증거로 사용하지 않습니다.
- 제한된 실제 파일럿은 진행할 수 있지만 전담 개발 투자는 보류합니다.
- 실제 기업 5곳에서 유료 파일럿 2개사와 확정 의도율 20%를 함께 충족할 때만 투자와 개발팀 인계를 다시 판단합니다.
- 현재 산출물의 스키마와 교체 지점은 재사용할 수 있지만, 합성 전환율을 운영 목표의 기준으로 그대로 사용하면 안 됩니다.
