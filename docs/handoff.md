# 개발팀 인계 문서

> 실제 조직에 인계한 기록이 아니라, 고객 검증 후 개발팀이 이어받을 때 필요한 내용을 정리한 인계용 문서입니다.

제출 포트폴리오 PDF는 당시 기록으로 보존합니다. 이후 화면과 검증 범위의 차이는 [제출본 정합성 문서](./submission-consistency.md), 현재 실행 결과는 [검증 보고서](../verification-report.md)를 확인해 주세요.

## 검증 대상

한 화면에서 자산 목록, 인수처 확인 자료, 매각 대금과 비용 절감액 합계, 재사용률과 수거 조건을 검토하고 확정하는 과정이 실제 승인 시간을 줄이는지 확인합니다.

## 재사용 가능한 산출물

- Drizzle 스키마, 순차 마이그레이션, 기존 데이터 보존 회귀 테스트
- 결정론적 매칭 엔진과 단위 테스트
- 인증, 조직 멤버십, 역할별 권한, 세션 경계
- 요약, 감사 로그, CSV API 계약
- 프로젝트 버전을 비교한 뒤 갱신하는 방식(CAS)을 적용한 재계산과 확정 트랜잭션, 실제 DB 경쟁 테스트
- 레코드 수정 시각을 비교해 수거와 정산의 동시 수정 충돌을 막고, 진행 상태별 필수 정보를 확인하는 규칙
- 사용자 행동 이벤트 정의
- 같은 결과를 재현하는 가상 데이터 생성기, 실행 노트북, 원본 CSV/JSON, 단일 HTML 보고서
- 성공 기준과 중단 조건, 후속 개발 검토 근거를 연결한 제품 판단 기록
- 반응형 화면과 디자인 토큰
- 자산 CSV와 인수처 확인 자료가 포함된 입찰 CSV 가져오기, 수거 상태 변경, 외부 결제사 확인 상태
- CI와 컨테이너 빌드

## 확정된 도메인 결정

- 금액은 만 원 단위 정수로 저장합니다.
- 추천안은 전체 자산 수량을 정확히 배정해야 합니다.
- 각 자산 항목은 사업자 확인을 마친 인수처의 입찰 하나에 전체 수량을 배정해야 합니다.
- 확정 전 초안은 다시 계산할 수 있고 확정 후에는 잠깁니다. 확정 요청에는 검토한 배분안 ID와 프로젝트 버전이 필요합니다.
- 매각 대금에 폐기비와 운반비 절감액을 더한 값을 `매각 대금과 비용 절감액 합계`로 정의합니다.
- 같은 날짜의 수거는 한 회차로 계산합니다.
- 확정은 반드시 감사 로그를 남깁니다.
- 정산 화면은 자금을 이체하지 않으며 외부 결제사의 확인 번호만 기록합니다.
- 프로젝트에 적용할 최소 매각 금액은 프로젝트 설정액과 자산별 최소 금액 합계 중 큰 값입니다.
- CSV 교체에는 같은 사용자, 파일, 프로젝트 버전에 발급된 15분 유효 미리보기 토큰이 필요합니다. SESSION_PEPPER 교체 시 기존 미리보기는 다시 실행해야 합니다.
- 숫자 공란과 동일 확인 자료의 상충하는 만료일은 거절하며, 계산 상한을 넘는 파일은 교체 전에 차단합니다.
- 모든 입찰에는 확인 담당자, 확인 시각과 확인 자료가 있어야 합니다. 확인 정보가 만료된 입찰은 매칭 후보에서 제외합니다.

## 한계와 교체 지점

| 현재 MVP | 운영 전환 시 |
| --- | --- |
| 조직 멤버십을 바탕으로 한 프로젝트 데이터 분리 | SSO 그룹 동기화와 멤버십 생성, 변경, 해지 절차 |
| 상한이 있는 작은 조합 탐색 | 큐 기반 비동기 제약 최적화 서비스 |
| 데모 계정 | OIDC SSO, MFA, 사용자 수명주기 |
| 외부 결제사 상태 수동 확인 | 결제사 계약, 서명된 웹훅, 이중부기 원장 |
| 자산 CSV와 확인을 마친 인수처 입찰 | 대용량 엑셀 가져오기, 확인 대기열, 원본 보존 |
| 단일 앱 트랜잭션 | 아웃박스와 이벤트를 이용한 수거 정보 전달 |
| 재현 가능한 가상 데이터 분석 | 실제 파일럿 이용 기록, 인터뷰 원문, 계약과 지불 증빙 |

## 현재 판단

- 아직 실제 고객에게 검증하지 않았으며 가상 데이터는 수요를 보여 주는 근거로 사용하지 않습니다.
- 실제 협력 기업이나 개발 조직이 확보된 상태가 아닙니다.
- 개인 프로젝트에서는 참여 기업을 모집하거나 영업하지 않았고, 계약도 체결하지 않았습니다.
- 실제 사업 환경에서 사업팀이 고객 검증을 진행한다면 기업 5곳 중 2곳 이상에서 유료 파일럿 참여 의향을 확인하고, 테스트 사용자 중 20% 이상이 배분안 확정 화면에 도달했을 때 후속 개발을 검토합니다.
- 가상 데이터만으로 후속 개발이나 개발팀 인계를 결정하지 않습니다.
- 현재 산출물의 스키마와 교체 지점은 재사용할 수 있지만, 가상 데이터에서 나온 전환율을 운영 목표로 그대로 사용하면 안 됩니다.

## 추가 개선 후 화면과 유지보수

- 입찰은 50건씩 조회합니다. URL의 `asset`, `selected`, `page`가 화면 조건이며, 내보내기는 이 조건과 무관한 전체 CSV입니다.
- CSV 가져오기는 접힌 ‘CSV로 입찰 가져오기’를 펼칩니다. 미리보기와 교체의 서명/버전 검증은 그대로 유지됩니다.
- 수거/정산에 배분안이 없으면 준비 전 안내를 표시합니다. 권한 없는 프로젝트나 없는 프로젝트는 기존처럼 404로 처리합니다.
- 스타일 수정은 `src/styles`의 해당 CSS Module에서 진행합니다. 루트 지역 클래스를 거치지 않는 전역 선택자를 추가하지 않습니다. 표의 스크롤 가능성은 공통 `TableScroll`이 관찰합니다.
- 대용량 가져오기 테스트는 실제 5,000행의 신규/기존 인수처 저장과 중간 실패 롤백을 포함하므로 커버리지 계측 환경에서는 일반 테스트보다 오래 걸릴 수 있습니다.
