REROUTE는 오피스 이전이나 폐점 때 처분해야 하는 사무 자산의 매각 대금, 폐기비와 운반비 절감액, 재사용률을 함께 비교하는 B2B 매칭 MVP입니다.
자산 담당자는 매각가, 폐기비와 운반비, 재사용률과 수거 일정을 여러 문서에서 확인한 뒤 승인 자료를 다시 정리해야 합니다.
이 비교 기준과 인수처 확인 자료를 한 화면에 모으면 확정 화면을 여는 사용자가 늘어날 것이라는 가설에서 시작했습니다.

제품 데모는 성수 오피스 이전을 가정한 샘플 자산 214개와 인수처 확인 자료가 포함된 입찰 11건으로 시작합니다.
매각 대금과 폐기 및 운반 비용 절감액을 각각 확인하고, 두 금액의 합계와 재사용률도 함께 비교합니다. 자산별 배분과 인수처 확인 자료도 한 화면에서 살펴볼 수 있습니다.
최소 매각 금액, 최소 재사용률과 최대 수거 횟수를 바꾸면 서버에서 배분안을 다시 계산합니다.
모든 자산을 배정할 수 없거나 자산 항목별 최소 매각 금액을 충족하지 못하면 확정할 수 없습니다.
인수처 확인 정보가 만료된 경우도 마찬가지입니다.

승인 권한이 있는 사용자가 배분안을 확정하면 자산별 배정이 수거 일정에 반영됩니다.
수거 담당자는 장소, 시간대, 차량과 진행 상태를 기록합니다.
정산 화면은 자금을 이체하지 않고 외부 결제사에서 확인한 입금과 지급 상태만 남깁니다.
재계산과 확정이 겹치지 않도록 프로젝트 버전 확인과 데이터베이스 트랜잭션을 적용했고, 중복 요청에는 같은 결과를 돌려줍니다.
실제 SQLite 트랜잭션을 동시에 실행해 재계산과 확정 중 하나만 반영되는지도 확인했습니다.

가설이 바뀌면 화면과 서버를 함께 수정할 수 있도록 Next.js 앱 라우터, React와 TypeScript를 사용했습니다.
서버 액션과 API는 Zod로 입력을 검증하고, Drizzle ORM과 libSQL은 관계형 테이블 16개에 상태를 저장합니다.
비밀번호는 scrypt로 해시하고, 데이터베이스 세션, 조직 멤버십과 역할별 권한으로 최소 권한 원칙을 적용했습니다.
다른 조직의 페이지와 API를 직접 열어도 데이터를 노출하지 않고 404를 반환하는지 E2E 테스트로 확인했습니다.
GitHub Actions는 린트, 타입 검사, 커버리지, 빌드와 브라우저 E2E 시나리오를 실행합니다.

다음은 실제 파일럿 전에 판단 기준을 점검한 결과입니다.
이 수치는 실제 고객 조사나 운영 기록이 아닙니다.
가상 사용자 10명과 가상 기업 5곳을 가정하고, 같은 결과를 재현할 수 있도록 난수 초기값을 고정해 5만 회 반복했습니다.
모든 성공 기준을 동시에 충족할 추정 확률은 18.8퍼센트, 배분안 확정 화면 진입과 유료 파일럿 기준을 함께 충족할 추정 확률은 30.9퍼센트였습니다.
예시 결과에서는 기업 5곳 중 1곳만 유료 파일럿에 참여해 기준인 2곳에 미치지 못했습니다.
따라서 소규모 실제 파일럿은 진행하되 전담 개발 인력 투입은 보류합니다.
실제 기업 5곳에서 지불 의사와 계약 주체를 확인한 뒤, 유료 파일럿에 참여한 기업이 2곳 이상이고 배분안 확정 화면 진입률이 20퍼센트 이상일 때만 개발 인력 투입을 다시 검토합니다.

이 개인 프로젝트의 기여도는 100퍼센트입니다.
문제 정의, 사업 가설, 제품 범위, 디자인, 프론트엔드, API, 데이터베이스, 보안, 테스트, 배포 구성과 문서화를 직접 수행했습니다.
AI 코딩 에이전트는 탐색, 반복 구현과 감사 보조에 사용했습니다.
권한 설정, 트랜잭션, 데이터 구조, 안전장치와 판단에 사용한 수치는 소스 코드, 실행 테스트와 별도 계산으로 직접 확인했습니다.
인계 문서에는 재사용할 데이터 구조, 검증 결과, 교체 지점과 운영 전에 보완할 내용을 정리했습니다.
REROUTE는 유료 파일럿 참여 기업 2곳과 확정 화면 진입률 20퍼센트를 개발 인력 투입의 재검토 기준으로 둔 풀스택 MVP입니다.
