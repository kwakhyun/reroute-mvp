# REROUTE 4분 제품 소개 구성

## 0:00–0:24 문제와 가설

“오피스 이전 현장에서는 매각가, 폐기비와 운반비, 재사용률과 수거 일정을 여러 문서에서 확인해야 합니다. REROUTE는 이 정보를 한 화면에서 비교하면 확정 화면을 여는 사용자가 늘어나는지 확인하는 MVP입니다.”

## 0:24–1:36 제품 흐름

“샘플 작업 공간은 오피스 이전 자산 214개와 인수처 확인 자료가 포함된 입찰 11건으로 시작합니다.
매각 대금과 절감한 폐기비, 운반비를 따로 확인하고, 두 금액의 합계와 재사용률, 수거 횟수도 함께 비교합니다. 자산별 배분과 인수처 확인 자료도 한 화면에서 살펴볼 수 있습니다.
조건이 바뀌면 배분안을 다시 계산하고, 승인 권한이 있는 사용자만 확정할 수 있습니다.”

## 1:36–2:16 풀스택 구현

“화면만 만든 시안이 아닙니다. Next.js 서버 액션과 API, Drizzle ORM과 libSQL 기반 관계형 테이블 16개, DB 세션, 조직별 데이터 분리, 중복 요청 방지와 동시 수정 충돌 처리를 구현했습니다. 재계산과 확정이 동시에 발생해도 하나의 상태만 반영되는지 실제 DB 경쟁 테스트로 확인했습니다.”

## 2:16–3:13 가상 데이터 분석과 개발 인력 투입 결정

“이 수치는 실제 고객 결과가 아닙니다. 가상 사용자 10명과 가상 기업 5곳을 가정해 판단 기준을 먼저 점검했습니다. 모든 기준을 동시에 충족할 추정 확률은 18.8%, 전담 개발 인력 투입 기준을 충족할 확률은 30.9%였습니다. 따라서 소규모 실제 파일럿은 진행하되 전담 개발 인력 투입은 보류합니다.”

## 3:13–4:01 기여도와 인계

“이 개인 프로젝트의 기여도는 100%입니다. AI 코딩 에이전트는 구현과 감사를 보조했고, 권한, 트랜잭션, 데이터 구조와 판단에 사용한 수치는 소스와 테스트, 별도 계산으로 직접 확인했습니다. 사업성이 확인되면 다른 개발팀이 이어받을 수 있도록 데이터 구조, 검증 결과와 교체 지점을 문서화했습니다.”
