# 기여도와 AI 협업 기준

## 기여도

이 프로젝트는 개인 프로젝트로 기여도는 100%입니다. 문제 정의, 사업 가설, 제품 범위, UX/UI, 애플리케이션 코드, 데이터 스키마, 보안 경계, 테스트, 배포, 문서화를 전부 직접 담당했습니다.

| 영역 | 직접 수행한 일 |
| --- | --- |
| 사업과 제품 | 초기 고객, 위험 가설, 퍼널, 개발 인력 투입 기준, 중단 조건 설계 |
| 디자인 | 정보 구조, 데스크톱과 모바일 화면, 접근성 상태, 시각 QA |
| 프론트엔드 | Next.js App Router, React 19, TypeScript, 서버와 클라이언트 컴포넌트 |
| 백엔드 | 서버 액션, REST API, Zod 입력 검증, 중복 실행과 버전 충돌 처리 |
| 데이터 | Drizzle ORM, libSQL, 관계형 테이블 16개, 마이그레이션과 회귀 테스트 |
| 보안 | scrypt 비밀번호, DB 세션, 조직별 데이터 분리, 최소 권한, nonce CSP, 로그인 제한 |
| 배포와 운영 | GitHub Actions, Vercel 구성, 원격 DB, 구조화 로그, 준비 상태 검사 |

## AI 코딩 에이전트 활용

OpenAI Codex를 코드 탐색, 반복 구현, 테스트 후보 작성, 코드 감사 보조와 문서 초안에 사용했습니다. 최종 아키텍처, 보안 경계, 데이터 모델, 테스트 범위와 판단 결과는 직접 검토했으며 모든 결과에 대한 책임은 프로젝트 저자에게 있습니다.

## 신뢰 경계

| 분류 | AI 결과 활용 | 직접 검증 방법 |
| --- | --- | --- |
| 낮은 위험 | 문구 초안, 스타일 반복, 테스트 후보 | 시각 검토, lint, 단위 테스트 |
| 중간 위험 | API 흐름, 서버 액션, 마이그레이션 초안 | 타입 검사, 통합 테스트, 실제 DB 회귀 테스트 |
| 높은 위험 | 인증, 권한, 조직별 데이터 분리, 트랜잭션, 지표 결론 | 소스 코드 줄 단위 검토, 실패 경로 테스트, 경쟁 실행, 별도 계산 |

AI 제안은 설명이 그럴듯하다는 이유만으로 받아들이지 않았습니다. 실패 경로와 데이터 일관성 규칙을 실제 실행으로 확인했을 때만 반영했습니다.

## 직접 확인한 항목

- 권한 경계: 다른 조직의 페이지와 API에 직접 접근해도 데이터를 노출하지 않고 404로 끝나는 E2E 테스트
- 동시성: 재계산과 확정을 실제 SQLite 트랜잭션으로 경쟁시켜 하나만 커밋되는지 확인
- 데이터 일관성: 자산 항목 수량 전체 배정, 확인 자료 만료, 최소 매각 금액과 수거 횟수를 강제하는 정책 테스트
- 가상 데이터 분석: 같은 난수 초기값으로 재생성, CSV와 JSON 별도 집계, 실제 고객 검증과 명확히 구분
- 배포: 파이프라인의 lint, 타입 검사, 커버리지, 빌드, 브라우저 여정 검증

AI 생성 여부와 관계없이 서비스에 남은 오류와 한계는 저자의 책임으로 다룹니다.
