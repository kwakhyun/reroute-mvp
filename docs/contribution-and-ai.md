# 기여도와 AI 협업 기준

## 기여도

이 프로젝트는 개인 프로젝트로 기여도는 100%입니다. 문제 정의, 사업 가설, 제품 범위, UX/UI, 애플리케이션 코드, 데이터 스키마, 보안 경계, 테스트, 배포, 문서화를 전부 직접 담당했습니다.

| 영역 | 직접 수행한 일 |
| --- | --- |
| 사업과 제품 | 초기 고객, 위험 가설, 퍼널, 투자 기준, 중단 조건 설계 |
| 디자인 | 정보 구조, 데스크톱과 모바일 화면, 접근성 상태, 시각 QA |
| 프론트엔드 | Next.js App Router, React 19, TypeScript, 서버와 클라이언트 컴포넌트 |
| 백엔드 | 서버 액션, REST API, Zod 입력 검증, 거래 멱등성과 버전 충돌 처리 |
| 데이터 | Drizzle ORM, libSQL, 16개 관계형 스키마, 마이그레이션과 회귀 테스트 |
| 보안 | scrypt 비밀번호, DB 세션, 조직 격리, 최소 권한, nonce CSP, 로그인 제한 |
| 배포와 운영 | GitHub Actions, Vercel, 원격 DB, 구조화 로깅, readiness 검사 |

## AI 코딩 에이전트 활용

OpenAI Codex를 탐색, 반복 구현, 테스트 케이스 후보, 코드 감사 보조, 문서 초안에 사용했습니다. AI가 생성한 결과를 사용했다는 사실과 저자의 책임은 서로 다른 문제입니다. 최종 아키텍처, 보안 경계, 데이터 모델, 테스트 범위, 의사결정 결론에 대한 책임은 프로젝트 저자에게 있습니다.

## 신뢰 경계

| 분류 | AI 결과 활용 | 직접 검증 방법 |
| --- | --- | --- |
| 낮은 위험 | 문구 초안, 스타일 반복, 테스트 후보 | 시각 검토, lint, 단위 테스트 |
| 중간 위험 | API 흐름, 서버 액션, 마이그레이션 초안 | 타입 검사, 통합 테스트, 실제 DB 회귀 테스트 |
| 높은 위험 | 인증, 권한, 테넌트 격리, 트랜잭션, 지표 결론 | 소스 라인 단위 검토, 부정 경로 테스트, 경쟁 실행, 독립 재계산 |

AI 제안을 수용하는 기준은 “설명이 그럴듯한가”가 아니라 “실패 경로와 정합성 규칙을 실행으로 증명했는가”입니다.

## 검증 근거

- 권한 경계: 다른 조직의 페이지와 API 직접 접근이 데이터 노출 없이 404로 끝나는 전체 여정 테스트
- 동시성: 재계산과 확정을 실제 SQLite 트랜잭션으로 경쟁시켜 하나만 커밋되는지 확인
- 데이터 정합성: 자산군 수량 전체 배정, 검증 만료, 회수 하한과 수거 횟수를 강제하는 정책 테스트
- 합성 분석: 고정 시드 재생성, CSV와 JSON 독립 재집계, 실제 고객 검증과의 명확한 분리
- 배포: 파이프라인의 lint, 타입 검사, 커버리지, 빌드, 브라우저 여정 검증

AI 생성 여부와 관계없이 서비스에 남은 오류와 한계는 저자의 책임으로 다룹니다.
